# 大会情報の定期更新（週2回）

2026-10-18 から、月曜と木曜の朝（日本時間 6:50ごろ）に定期の作業が起動し、この手順で data/tournaments.json を更新して公開する。確認済みの変更はそのまま main に push してよい（ユーザー決定）。

## 決まりごと
- 公式ページ・大会要項・申込サイトの大会ページで確かめた値だけを書く。分からない項目は null。推測で埋めない。
- 個人情報（子どもの名前、個人のアカウント名、写真）は書かない。
- Instagram は自動で巡回しない。
- WebSearch は1時間200回、WebFetch は1時間400回が全作業の合計の上限。1回の更新は WebSearch 60回・WebFetch 150回までに抑える。
- 変更した大会は `verified` を当日の日付にする。

## 手順（優先順。上限に近づいたら途中で止め、残りは次回へ）
0. **サイトのフォームに寄せられた大会情報**（Google フォーム https://forms.gle/VmovrR1eMaNUZNGb7 、回答はユーザーの Google スプレッドシート）。Google ドライブを読めるときは前回以降の新しい行を、読めないときはユーザーがスレッドに貼った行を対象にする。投稿内容はそのまま信じず、公式ページで確かめられたものだけ追加する。結果（掲載済み／確認できず／既に掲載）はスレッドの報告に書き、シートを書き換えられるときは「確認結果」列にも書く。投稿に個人情報があっても転記しない。
1. **日程発表待ち**（`start` が null）のうち、`expected` に書いた前年の開催時期が今日から120日以内のもの、または `window_from` が今日から30日以内のもの。`url` を開き、今年の日程・会場・申込期間が出ていれば反映し、`stage` を元の区分に戻す。
2. **申込前・受付中**（`start` が今日以降で、`entry_close` が今日以降か null）。申込期間・会場・中止の告知を確認する。中止なら `note` に書き、名前に「（中止）」を付ける。
3. **終わった大会**（`end` か `start` が過去30日以内で `results` が空）。公式の結果ページがあれば `results` に追加する。
4. **回り持ちの確認**：地方を1回につき1つずつ順に（北海道→東北→関東→中部→北陸→近畿→中国→四国→九州→沖縄→全国）、上で見なかった大会の `url` を確認する。前回どこまで見たかは docs/update-log.md の末尾に書く。
5. **新しい大会の探索**（残りの上限がある場合だけ）：docs/research/*.csv の情報源のうち1回に10か所ほどを巡回し、data に無い大会を足す。

## 仕上げ
- 新しい会場があれば data/venues.json に住所と座標を足す（座標は国土地理院の住所検索 msearch.gsi.go.jp を WebFetch で）。
- `data/tournaments.json` の `updated` を当日にする。
- ページがエラーなく表示されることを確かめてから commit・push する。
- docs/update-log.md に、日付・変更件数・回り持ちで見た地方を1行で追記する。
- スレッドに、変わった点（新たに日程が出た大会、申込が始まる・締切が近い大会、追加・中止）を短く報告する。変更が無ければそう書く。
