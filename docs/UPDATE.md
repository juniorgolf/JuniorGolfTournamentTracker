# 大会情報の定期更新（週2回）

2026-10-18 から、月曜と木曜の朝（日本時間 6:50ごろ）に定期の作業が起動し、この手順で data/tournaments.json を更新して公開する。確認済みの変更はそのまま main に push してよい（ユーザー決定）。

## 決まりごと
- 公式ページ・大会要項・申込サイトの大会ページで確かめた値だけを書く。分からない項目は null。推測で埋めない。
- 個人情報（子どもの名前、個人のアカウント名、写真）は書かない。
- Instagram は自動で巡回しない。
- WebSearch は1時間200回、WebFetch は1時間400回が全作業の合計の上限。1回の更新は WebSearch 60回・WebFetch 150回までに抑える。
- 変更した大会は `verified` を当日の日付にする。

## 手順（優先順。上限に近づいたら途中で止め、残りは次回へ）
0. **サイトのフォームに寄せられた大会情報**（Google フォーム https://forms.gle/VmovrR1eMaNUZNGb7 ）。回答シート「ジュニアゴルフ大会情報提供フォーム（回答）」spreadsheetId `1JNSbZ--qqPvDn2baxu_Qh8TniWrdACFtQoT7cdRH7pI`、シート「フォームの回答 1」。列は A タイムスタンプ／B 大会名／C URL／D 開催日／E 会場／F 都道府県／G 主催者／H 対象／I その他／J 結果確認。Google Sheets コネクタで読み、**J が空の行**を対象にする。投稿内容はそのまま信じず、公式ページで確かめられたものだけ追加する。各行の J に「掲載済み（YYYY-MM-DD）」「既に掲載」「確認できず（理由）」「対象外（理由）」のどれかを書く。読めないときはユーザーがスレッドに貼った行を対象にする。投稿に個人情報があっても転記しない。
まず `python3 scripts/priority.py` を実行し、確認する大会の一覧（見落としの影響が大きい順）を出す。2026-10-20 ユーザー決定：件数が増えても古い情報が残らないよう、地方の回り持ちではなくこの優先順で確認する。
1. **A 申込締切・開催が近い**（締切が45日以内、締切不明なら開催が60日以内）。7日以内に確認済みのものは、締切・開催が7日以内でなければ除く（D の確認に枠を残すため）。締切が近い順に、申込期間・会場・中止の告知を確認する。中止なら `note` に書き、名前に「（中止）」を付ける。
2. **B 日程発表の時期が来た**（日程発表待ちで `window_from` が30日以内か過ぎたもの）。`url` を開き、今年の日程・会場・申込期間が出ていれば反映し、`stage` を元の区分に戻す。まだなら `verified` だけ当日にする（次回は後回しになる）。`window_from` が無い発表待ちは D に入る。
3. **C 結果待ち**（過去30日以内に終わり `results` が空）。公式の結果ページがあれば `results` に追加する。終わった大会は data/past/<開催年>.json に移してあるので、そのファイルを直す。
4. **D 確認が古い**（A〜C 以外で、確認日 `verified` が古い順）。上限の残りで上から順に `url` を確認する。日程が変わっていなくても、確認したら `verified` を当日にする。海外（overseas: true）は US Kids Golf（tournaments.uskidsgolf.com）・FCG（futurechampionsgolf.com）などの公式ページで確認し、日付は現地の日付、締切の時間帯は note に書く。米国内の US Kids ローカルツアーは載せない（2026-10-19 決定）。調査の決めごとは /mnt/project-files/research/overseas-2026-10-19/BRIEF.md。
5. **新しい大会の探索**（残りの上限がある場合だけ）：docs/research/*.csv の情報源のうち1回に10か所ほどを巡回し、data に無い大会を足す（重複の確認は data/tournaments.json と data/past/*.json の両方で行う）。

## 仕上げ
- pref に「全国」は使わない（2026-10-20 ユーザー決定でエリアの「全国大会」を廃止）。全国規模の大会も予選・決勝ごとに分け、会場（日程発表待ちなら前年の会場）の都道府県を pref にする。日程発表待ちの大会は、前年の会場が公式で分かれば `prev_venue`（venues.json にある会場名）を入れる。地図ではその会場に「日程未定（前年の会場）」として出る。日程が出たら `prev_venue` は消してよい。
- 新しい会場があれば data/venues.json に住所と座標を足す（座標は国土地理院の住所検索 msearch.gsi.go.jp を WebFetch で）。
- **前回の結果**（2026-10-20 ユーザー決定）：これからの大会・日程発表待ちには `prev_results`（{year, name, links:[{label,url}]}：同じ大会の一つ前の回の公式結果）を付ける。C で結果を足した大会に次の回の記録（日程発表待ちなど）があれば、その `prev_results` も更新する。新しい大会を足すときも前回の公式結果があれば付ける。名前・スコアは書き写さない。
- `python3 scripts/prev_link.py` を実行し、前回の結果が無い大会に、終わった大会（data/past）の結果を付ける。会場ごとに開くシリーズ（石川遼カップ・東横イン・大東建託・小平智・ジュニアプレーヤーズの地区大会など）は、同じ会場の前回を優先して会場ごとに付ける（2026-10-20 ユーザー要望：シリーズでまとめず個別に）。日程発表待ちでシリーズ1件にまとめている大会は、会場と日程が発表されたら会場ごとの大会に分けて登録する。
- `python3 scripts/archive.py` を実行し、終わった大会を data/tournaments.json から data/past/<開始日の年>.json へ移す（2026-10-20 ユーザー決定：最初に読み込むデータを軽く保つため、終了した大会は年ごとの別ファイルにし、サイトでは必要なときだけ読む）。
- `data/tournaments.json` の `updated` を当日にする。
- ページがエラーなく表示されることを確かめてから commit・push する。
- docs/update-log.md に、日付・変更件数・A〜D をそれぞれ何件確認したかを1行で追記する。
- スレッドに、変わった点（新たに日程が出た大会、申込が始まる・締切が近い大会、追加・中止）を短く報告する。変更が無ければそう書く。
