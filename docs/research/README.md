## Webサイト構築の方針案
1. **データが本体**：大会1件＝1レコード（大会名・主催・対象学年・都県・会場・開催日・申込開始・申込締切・申込方法URL・公式URL・最終確認日）。最初は人手で確認してCSV/YAMLに入れる。
2. **画面**：「いま申込受付中」「締切まで○日」を最上部に。都県・学年・主催で絞り込み、月カレンダー表示。各大会に公式ページへのリンクと最終確認日を必ず出す（誤情報の責任範囲を明確に）。
3. **通知**：カレンダー登録用 ICS フィードを最初に用意（Google/iPhoneカレンダーで申込開始・締切がそのまま通知される）。メール/LINE通知は後から。
4. **更新の自動化**：上記ソースのページを定期取得して「変化があったら知らせる」監視を付け、更新は人が確認して反映。完全自動の抽出は書式がバラバラなので後回し。
5. **技術**：静的サイト（例：Astro）＋データファイル、GitHub Pages か Cloudflare Pages で無料公開。サーバー不要で保守が軽い。
6. **進め方**：MVPは2027年シーズン（1〜6月）の関東小学生向け大会30〜50件を入力して公開 → 監視自動化 → 他地域へ拡大。
